# 眼镜刚体六自由度追踪——设计说明

> 范围：**本轮只实现阶段一**（摄像头内参标定 + 眼镜标记追踪 + 无鼠标验证工具）。
> 阶段二（屏幕几何与指向控制）、阶段三（个人校准与验收）**只写设计，不实现**，不接管真实鼠标，
> 不改变现有默认 `pointer_source`。
>
> 术语澄清：本功能是**头部指向控制**（用眼镜刚体位姿推算头部朝向），**不是眼球注视追踪**。
> 仅追踪眼镜无法知道眼睛看哪里。本设计不建立头颈解剖模型：脖子与身体带来的头部位移，
> 直接由眼镜六自由度位姿体现。

## 2. 坐标系与单位（强制约定）

| 坐标系 | 定义 | 单位 |
|---|---|---|
| **相机坐标系** `C` | OpenCV 约定：**X 向右、Y 向下、Z 向前**（光轴方向）；原点在光心 | 米 |
| **标记坐标系** `M` | ArUco 标记平面：**X 向右、Y 向上、Z 指向观察者**（垂直于标记平面向外） | 米 |
| **显示坐标系** | 仅叠加层使用：图像像素，原点左上，X 右 Y 下 | 像素 |

- **所有物理平移内部一律用米**；UI 可换算为毫米显示。
- 标记坐标系与 `SOLVEPNP_IPPE_SQUARE` 要求的模型点顺序严格对应（见 §5.3）。
- 旋转以 `rotation_matrix` 与规范化 `quaternion` 输出；欧拉角**只用于 UI 展示**。

### 2.1 镜像规则（强制）

1. 几何检测、摄像头标定、PnP **统一使用未镜像的原始图像**。
2. 自拍镜像**只用于显示**；现有手部 handedness 逻辑（`camera.mirror=true` → `mirror_handedness=false`）保持不变。
3. `camera.py` 只做**向后兼容**扩展：新增 `read_raw()` 返回未镜像帧，`read()` 行为不变。
4. **不对镜像图像套用未镜像标定参数**（镜像会改变内参矩阵中的主点与姿态手性）。
5. 标定分辨率与运行分辨率不一致时，**本轮拒绝使用并提示重标定**，禁止静默复用。

## 3. 数据流

```
camera.read_raw()  ──►  灰度  ──►  ArUco 检测（未镜像）
        │                              │
        │                              ├─► cornerSubPix 亚像素精化
        │                              ▼
        │                     solvePnPGeneric(IPPE_SQUARE) 候选解
        │                              ▼
        │                     质量门（正深度 / 旋转有效 / 重投影 / 面积）
        │                              ▼
        │                     歧义判定 + 时间连续性辅助选解
        │                              ▼
        │                     异常拒绝（速度 / 角速度 / 时间戳）
        │                              ▼
        │                     滤波：四元数 SLERP + 平移独立状态
        │                              ▼
        │                        GlassesPose(valid, status, ...)
        ▼
camera.read()（镜像）──►  仅显示：叠加层绘制标记框、坐标轴、文字
```

运行期间不保存、不上传任何图像；只保存数值参数与统计量。

## 4. 阶段一（A）：摄像头内参标定

### 4.1 标定板定义（默认值，全部可配置）

| 项 | 默认 | 说明 |
|---|---|---|
| `dictionary` | `DICT_5X5_50` | ArUco 字典，必须与打印板一致 |
| `squares_x` × `squares_y` | `8` × `6` | ChArUco 棋盘方格数（**乘积必须为偶数**，否则 marker 数量不是整数） |
| `square_length_m` | `0.025` | 方格边长（米）——打印后必须实测核验 |
| `marker_length_m` | `0.018` | 标记边长（米），必须小于方格边长 |
| 内部角点数 | `(8-1)×(6-1) = 35` | 用于覆盖度与有效性判断 |

板尺寸 8×0.025 = **200 mm 宽**、6×0.025 = **150 mm 高**，可 100% 打印在 A4（210×297 mm）上。

### 4.2 采集流程（`--calibrate-camera`）

- 实时预览，窗口显示当前检测到的 ChArUco 角点数与已采集视图数。
- `SPACE`：当本帧角点数 ≥ `min_corners_per_view` 时采集一个视图。
- `c`：结束采集并计算标定（视图数不足会拒绝并提示）。
- `ESC` / `q`：放弃并退出。
- **标定模式不实例化真实鼠标控制，不注册任何点击动作。**

### 4.3 质量检查（不满足即给出明确中文提示）

| 检查 | 判据 | 处理 |
|---|---|---|
| 样本不足 | 有效视图 < `min_views`（默认 15） | 拒绝标定，提示继续采集 |
| 覆盖不足 | 角点未覆盖画面 3×3 网格中至少 `coverage_min_cells` 个格子 | 警告（不阻断），提示补拍边缘/四角 |
| 重复视角 | 新视图角点分布与其他视图过于接近（归一化角点均方距离 < 阈值） | 拒绝该视图并提示换角度 |
| 无效角点 | 角点数 < `min_corners_per_view`、坐标非有限 | 丢弃该视图 |
| 非有限值 | 标定结果含 NaN/Inf | 拒绝保存 |

> 建议采集 **15–20 个不同倾角与画面位置**的有效视图；数量不是唯一质量标准，覆盖与多样性同样重要。
> 20 个视图只是经验下限，不构成精度保证。

### 4.4 输出与保存

- 产出 `camera_matrix`（3×3）、`dist_coeffs`（1×5 或 1×8）、`image_size`(w,h)。
- 输出**整体 RMS** 与**逐视图重投影误差**（像素）。
- 保存到 `data/camera_calibration.json`（JSON，**不用 pickle**），覆盖前自动备份为
  `data/camera_calibration.<时间戳>.bak.json`。
- 文件内容：`schema_version`、`board`（字典/行列/边长/单位）、`image_size`、`saved_at`、
  `metrics`（rms、per_view_rms、num_views、coverage）、`camera_matrix`、`dist_coeffs`。

> **不得**把 OpenCV 返回的 RMS 当成参数协方差或绝对姿态精度——它只是重投影残差的平方根。

### 4.5 可打印标定板

`--write-charuco-board PATH` 生成按物理尺寸绘制的标定板 PNG，并在图上标注方格边长与标记边长。
打印要求写在图上与 README 中：

- 必须 **100% 实际尺寸**打印，**禁止**「适合页面 / Fit to page」。
- 打印后**必须用直尺实测**若干方格边长，与配置值一致才可使用。

**实现注意（实测发现的坑）**：`cv2.aruco.CharucoBoard.generateImage(outSize, marginSize)`
会先把留白算进 ``outSize`` **再缩掉**，导致方格物理尺寸静默失真
（8×6、25 mm、4000 px/m 时应为 100 px/格，传 `marginSize=40` 后只剩 85.99 px/格）。
因此实现改为 `marginSize=0` 精确渲染（方格像素边长 = `square_length_m * pixels_per_meter`），
标注文字用 `cv2.copyMakeBorder` 加在**板外**留白里；导出后还会用
`measure_rendered_square_px()` 实测相邻角点间距做自检，偏差 > 0.5 px 直接拒绝导出。
若 Pillow 可用，PNG 会写入物理分辨率元数据（4000 px/m ≈ 101.6 dpi），
让打印机「实际大小」更接近真实尺寸；Pillow 不可用时退回 OpenCV 写入，像素尺寸不受影响。

## 5. 阶段一（B）：眼镜标记追踪

### 5.1 标记安装

- 初版使用**单个 ArUco 标记**，固定在镜框或轻便刚性支架上。
- `marker_id`、`dictionary`、`marker_size_m` 可配置；**真实边长必须由用户实测，程序不猜**。
- 安装位置尽量不遮挡眼睛、不影响眨眼检测（不要挡住 EAR 所需的上下眼睑区域）。
- 精度约束：标记越小 → 像素尺寸越小 → 位姿越差；反光、侧转、遮挡都会显著降低精度。

#### 5.1.1 可打印单标记图纸（`--write-aruco-marker`）

`--write-aruco-marker PATH` 生成一张「标记 + 白边 + 说明 + 0–100 mm 参考条」的 PNG，
参数（`dictionary` / `marker_id` / `marker_size_m`）直接读 `glasses_tracking`，避免图纸与配置不一致。

- **黑框语义**：`marker_size_m` 指**黑色边框外缘到外缘**的边长（即 `generateImageMarker`
  输出图像的整幅边长），与 §5.3 的模型点 ±s/2 严格对应；白边（quiet zone）不计入边长。
- **像素吸附**：边长先吸附到「每格整数像素」（`cells = markerSize + 2×borderBits`，DICT_5X5 默认 7 格），
  再由 `px/m = marker_px / marker_size_m` 反推真实比例。默认 30 mm → 357 px（51 px/格）、
  11900 px/m ≈ 302.26 dpi；pHYs 写整数 px/m，因此「100% 打印」时黑框正好 30.00 mm。
- **自检**：导出前用 `measure_marker_bbox_px()` 实测黑框连通域边长与左上角（必须严格相等），
  再用 `detect_marker_ids()` 确认渲染结果能被检出；白边不足一格时自动放大到一格。
- **实测兜底**：图纸自带 0–100 mm 毫米刻度参考条，用户用真尺复核后把实测值写回
  `glasses_tracking.marker_size_m`；程序无法知道纸上真实尺寸，不猜。
- **绘制细节**：刻度线用 `cv2.rectangle` 而非 `cv2.line`——后者粗线会把两端各外扩半个线宽，
  实测会把 100 mm 参考条画成约 100.4 mm；图上文字必须全 ASCII（`cv2.putText` 不支持中文）。

### 5.2 检测

1. `cv2.aruco.detectMarkers`（灰度、未镜像）。
2. 命中目标 `marker_id` 后，对其 4 个角点做 `cv2.cornerSubPix` 亚像素精化。
3. 计算 `marker_area_px`（角点凸包面积）用于 `TOO_SMALL` 判定。

### 5.3 位姿求解（严格遵循 IPPE_SQUARE 顺序）

模型点必须严格按 OpenCV 对 `SOLVEPNP_IPPE_SQUARE` 的要求排列（**Y 轴向上**）：

```
(-s/2, +s/2, 0)   左上
(+s/2, +s/2, 0)   右上
(+s/2, -s/2, 0)   右下
(-s/2, -s/2, 0)   左下      s = marker_size_m
```

`detectMarkers` 返回的角点是**图像顺序**（左上→右上→右下→左下，Y 向下），与上表一一对应，
因此该顺序必须硬编码且被测试锁死（见 §9 角点顺序测试）。

调用 `cv2.solvePnPGeneric(objp, imgp, camera_matrix, dist_coeffs, flags=cv2.SOLVEPNP_IPPE_SQUARE)`，
返回多个候选 `(rvec, tvec, reprojection_error)`。

### 5.4 候选解选择

对每个候选依次检查：

1. **正深度**：`tvec[2] > 0`（标记必须在相机前方）。
2. **旋转有效性**：`Rodrigues(rvec)` 正交性（`RᵀR ≈ I`，`det(R) ≈ +1`）。
3. **重投影**：`reprojection_error_px <= max_reprojection_error_px`。
4. **时间连续性**（仅辅助）：与上一有效姿态的旋转夹角/平移差的加权代价最小。

**歧义处理**：若最优与次优候选的重投影误差接近（差 < `ambiguity_reproj_margin_px`）
**且**两者旋转夹角大于 `ambiguity_angle_deg`，则判为 `AMBIGUOUS`。
首次获取或长时间丢失后（无可靠历史姿态）出现该情况时，**不强行输出可信姿态**。

**实现补充（实测后的修正）**：单标记是正方形平面目标，两个 IPPE 解本身就是镜面对称的一对。
用合成数据（f=1000、边长 40 mm、深度 0.45 m、角点噪声 σ=0.25 px）实测：
两解的逐帧重投影 RMS 差中位数只有 **0.17 px**，而单帧角点噪声本身就有 0.25 px 量级，
因此**单帧误差差根本无法统计区分两解**。若直接套用固定阈值 0.5 px，
84% 的帧都会被判为 `AMBIGUOUS`，追踪器将永远无法进入 `TRACKING`。
据此实现如下（仍然遵守「不可靠就不输出」的原则）：

1. **有近期参考姿态**（上一有效帧且间隔 ≤ `gap_reset_s`）：按旋转连续性在两解之间择一，
   并在 `resolve_note` 中说明「按时间连续性择一」。连续性只用于在**都通过质量检查**的候选之间选择。
2. **冷启动 / 长时间丢失后**：进入**多帧证据累积**。按旋转夹角（容差 `ambiguity_branch_angle_deg`）
   把每帧的候选归并到最多两支（一支每帧最多接收一个候选，否则同帧两解会被并进同一支而永远无法分开），
   累积每支的平均重投影 RMS 与逐帧胜出次数。
   当累积帧数 ≥ `acquisition_frames` 且
   「平均 RMS 差 ≥ `ambiguity_evidence_px`」**且**「较优支在 ≥ 75% 的帧中胜出」时，才输出较优解；
   否则继续累积并保持 `AMBIGUOUS`，界面提示用户保持标记可见。
3. 两支误差确实无法区分（例如完全正对镜头）时**始终**报 `AMBIGUOUS`，不猜。

### 5.4.1 显示用欧拉角（只用于 UI，不参与几何）

`direction_angles_deg()` 以「标记正面正对摄像头」为 0 基准（标记坐标系 +Z 指向摄像头，
正对时法向为 (0,0,-1)，故基准取 `-normal_z`）：

- `yaw`：标记法向朝**图像右侧**偏转为正；
- `pitch`：标记法向朝**图像上方**偏转为正（抬头为正）；
- `roll`：标记平面内绕法向的旋转（歪头）。

正对摄像头时三个角都是 0 度。旋转平滑与角度差一律用四元数/旋转矩阵几何计算，
绝不直接对欧拉角相减或求标准差（跨 ±180° 会得到假值）。

### 5.5 输出结构

| 字段 | 说明 |
|---|---|
| `valid` | 本帧是否产出可信位姿 |
| `status` | 见 §5.6 |
| `timestamp` | 真实时间戳（秒，`perf_counter`） |
| `marker_id` | 标记 ID |
| `corners_px` | 4×2 亚像素角点（未镜像图像） |
| `rotation_matrix` | 3×3，未镜像相机坐标系 |
| `quaternion` | 规范化四元数 `(w,x,y,z)`，符号连续 |
| `translation_m` | (3,) 米 |
| `reprojection_error_px` | 像素 |
| `marker_area_px` | 角点凸包面积 |
| `raw_*` / `smoothed_*` | 原始与平滑后的位姿（两者都保留） |
| `reason` | 歧义或失效原因（中文可读） |
| `resolve_note` | 选解说明（例如「按时间连续性择一」「已用多帧重投影证据消除双解歧义」） |
| `stale` | 是否只是 UI 保留的最后姿态（`stale=True` 时**不是**有效观测） |

### 5.6 状态机

| 状态 | 含义 |
|---|---|
| `NO_MARKER` | 本帧未检测到目标标记 |
| `TOO_SMALL` | 标记面积 < `min_marker_area_px` |
| `AMBIGUOUS` | 候选解无法可靠区分 |
| `BAD_REPROJECTION` | 重投影误差超阈值 |
| `MOTION_OUTLIER` | 平动/转动速度超阈值，或时间戳异常 |
| `CALIBRATION_MISMATCH` | 内参文件缺失，或分辨率与运行分辨率不一致 |
| `STABILIZING` | 已重新获取，正在累积连续有效观测 |
| `TRACKING` | 稳定跟踪中 |

**实现注意**：`stabilize_frames` 判定**只能**看连续有效帧计数。
如果同时要求「`_trusted` 已为真」，会出现死锁——`_trusted` 只在非 STABILIZING 分支置位，
于是追踪器永远停在 `STABILIZING`（合成测试已覆盖该回归）。

### 5.7 异常拒绝与滤波（原则：先判断可信，再平滑）

- 速度/角速度由**真实时间戳**计算；阈值全部可配置。
- **长时间间隔后不沿用旧速度判据**（`gap_reset_s` 之后重置速度与滤波状态）。
- 旋转差用**旋转几何**（四元数夹角 / `R1ᵀR2` 的转角）计算，**不直接相减欧拉角**。
- 旋转平滑使用四元数**符号连续化 + SLERP**；平移使用**独立**滤波状态，不与眼控/手控共用。
- 丢失检测**立即**把当前观测标记为无效；UI 可短暂保留最后姿态，但必须标记 **stale**，不得当作有效观测。
- 重新获取后需连续 `stabilize_frames` 个有效观测才恢复 `TRACKING`；恢复时重置陈旧滤波状态，避免沿丢失前轨迹缓慢滑回。
- 统计：有效帧率、各失效状态计数、有效观测比例。

## 6. 阶段一（C）：`--glasses-test` 无鼠标验证模式

- 只打开摄像头与调试窗口；**不实例化真实鼠标控制**，**不注册任何会触发点击的动作**。
- 退出：`ESC`（主）与 `q`；`F10` 按项目可行方式保留（本地窗口按键，非全局热键）。
- 叠加显示：标记边界与 4 个角点、`ID`、**三色坐标轴**（X 红 / Y 绿 / Z 蓝）、`Status`、
  `Reproj`、`Translation`（m 与 mm）、`Yaw/Pitch/Roll`、`TrackingFPS`、有效观测比例。
- **有效性 vs 陈旧**必须显著区分：有效用绿字、stale 用黄字并标注 `STALE`。
- 内参文件缺失 → 直接提示「请先运行 `main.py --calibrate-camera`」并退出（不使用粗略焦距代替）。
- 定时（默认每 `stats_period_s=2s`）输出数值统计；静止稳定性统计窗口默认 10s：
  - 平移：位置标准差（mm）；
  - 旋转：**对窗口内参考四元数的夹角偏差**求均值/标准差（度），**不对跨 ±180° 的欧拉角直接求标准差**。
- 不记录图像。
- 可选 FaceMesh 对比（默认关闭，影响 FPS 时保持关闭）：同一静止区间比较角抖动与离群率；
  两者坐标系未对齐前，不把绝对 yaw 差当作精度误差。

## 7. 阶段二设计（本轮不实现）：屏幕几何与指向控制

### 7.1 待估计量

1. 屏幕相对摄像头的刚体变换 `T_cam_screen` 与屏幕**物理宽高**（米）。
2. 屏幕像素坐标 ↔ 屏幕物理平面坐标的对应（原点与方向明确）。
3. 个人指向方向参数（少量）。

### 7.2 可辨识性约束

- **不同时**自由拟合「屏幕几何 + 射线起点 + 射线方向」，否则不可辨识。
- 初版**固定或强约束眼镜坐标系中的射线起点**（例如取标记中心沿标记 -Z 偏移固定距离），
  **只拟合方向偏差**（2 个角度参数）。

### 7.3 外参标定（摄像头看不到自己所在的屏幕）

装在屏幕上方、朝用户拍摄的摄像头**通常看不到屏幕或边框**，因此不能假设它能直接观察屏幕标记。
必须提供可执行选项，按推荐顺序：

1. **人工测量 + 少量屏幕目标点微调**（当前硬件首选）
   - 用卷尺/量角器测出摄像头光心相对屏幕平面的位置与姿态，给出误差限制（例如 ±5 mm、±1°）。
   - 屏幕显示若干已知像素位置的目标点，用户注视/用眼镜对准，做小规模优化（只优化已受约束的自由度）。
2. **刚性标定支架**：支架同时可见于摄像头、且与屏幕有已知几何关系（例如贴有标记的刚性连杆固定在屏幕上）。
3. **临时外部相机做变换链**：外参相机同时看到屏幕与眼镜标记，再做链式变换（需额外硬件）。

> 摄像头或屏幕一经移动，必须重新做外参标定。方案 1 的误差限必须写进验收指标。

### 7.4 指向与求交

- 由眼镜位姿 `T_cam_marker` 与固定的射线起点/方向 → 相机坐标系下的射线。
- 与屏幕平面求交，得到物理平面坐标 → 转屏幕像素。
- **明确策略**：近平行（`|n·d| < eps_parallel`）、负向交点（交点在相机后方）、非有限交点、离屏交点。

### 7.5 失效与集成

- 追踪失效（非 `TRACKING`、stale、`CALIBRATION_MISMATCH`）时**冻结光标**，
  **不自动切回**面部/眼控/手控。
- 新来源与现有模式**显式选择**（新增独立配置项），不改变默认 `pointer_source`。
- **不复用** `MODEL_VERSION=3` 的眼控校准文件存储新几何模型；新几何模型用独立文件与独立版本号。
- 保留眼睛点击（眨眼 → 单击/右键/双击/拖拽）；确认**眨眼冻结作用于最终光标输出**，而不只是眼控分支。

## 8. 阶段三设计（本轮不实现）：个人校准与验收

- 校准：屏幕中心 + 周边若干目标点，做头部指向的个人方向校准（参数少、强正则）。
- 验证必须用**未参与校准**的目标与身体姿势：
  正常坐姿、左右平移、前倾、后靠、不同转头角度、标记短时遮挡与重新获取。
- 指标分开统计：静止抖动、目标误差（px 与 cm）、丢失率、恢复跳变、交互延迟。
- **不把训练样本上的误差当成独立验证误差**。

## 9. 测试要求（阶段一，全部合成、不开摄像头、不动鼠标）

- 内参与标定文件：保存/加载/版本/分辨率检查/备份/非法值。
- ArUco 检测与**角点顺序**。
- 已知内参 + 已知位姿生成投影点 → 恢复位姿与重投影误差。
- IPPE 候选：正深度、连续性、歧义处理。
- 失效：缺失标记、面积过小、重投影过大、NaN/Inf、运动离群。
- 四元数符号等价、角度回绕、旋转平滑。
- 时间戳异常、长间隔、丢失与重新获取。
- 镜像只影响显示，不改变几何结果。
- `--glasses-test` 不创建真实鼠标控制、不触发点击。
- 原有手控 handedness 与 UI 映射回归。
- 缺省配置向后兼容；未知/非法字段按现有机制报错。
- 原有全量测试仍通过。

## 11. 已知限制与风险

- 单标记是**平面**目标，正对时存在 IPPE 平面二义性，本设计以「歧义则拒绝输出」处理。
- 小标记在远距离下像素面积小，位姿噪声急剧增大（`TOO_SMALL` 门槛只是下限）。
- 眼镜在鼻梁上滑动会造成位姿漂移，阶段二需要重新校准或增加约束。
- 内参与标记尺寸的误差会直接进入**米制**平移结果；本设计不做「粗略焦距」的降级输出。
- 单标记位姿存在固有尺度偏差：亚像素角点位于黑框最外侧像素中心，等效边长比实体短约 1 像素，
  平移/深度相对偏差约为 `1 / marker_px`（按本轮图纸合成回放：约 60 px 的 30 mm 标记在 0.5 m 处
  读数约 −1.4%）；这是方法本身的偏差，不是标定误差，阶段二求交时需按此留裕量。
- 本轮不涉及真实鼠标接管，眼镜模式**尚未控制真实光标**。
