# 任务：为 EyeMouse 增加眼镜刚体六自由度追踪

## 一、项目基线与总体目标

项目目录：D:\TEST\eye_MOUSE。

已知项目报告基线：
- 地址表 docs/change_manifest.json 第 374 条。
- 全量测试 179 passed。
- 默认右手移动光标，眼睛负责眨眼单击、右键、双击与拖拽。

开始前读取实际代码和当前地址表，确认真实基线；以上数字不是要求硬编码的目标。

新功能目标：
用固定在眼镜上的已知视觉标记，估计眼镜相对摄像头的三维旋转与平移。后续通过“头部指向线与屏幕平面求交”控制光标。

这是“头部指向控制”，不是眼球注视追踪。不要声称仅追踪眼镜就能知道眼睛看哪里。

不建立头颈解剖模型：脖子、身体运动造成的头部位移，直接由眼镜六自由度位姿体现。

## 五、阶段一：摄像头内参标定

建议新增 eyemouse/camera_calibration.py，按项目架构调整具体命名。

实现：
- 使用已知布局的 ChArUco 标定板采集角点数值。
- 明确定义字典、行列数、方格边长、标记边长和单位。
- 内部长度统一为米。
- 标定得到 camera_matrix、dist_coeffs、image_size。
- 输出整体及逐视图重投影误差。
- 对覆盖不足、重复视角、无效角点、非有限值及不足样本给出明确提示。
- 建议至少采集 15–20 个不同倾角与画面位置的有效视图，数量不作为唯一质量标准。
- 保存到 data/camera_calibration.json，包含 schema 版本、板参数、标定分辨率、采样与质量指标。
- 覆盖前自动备份。
- 使用 JSON，不使用 pickle。

CLI：
--calibrate-camera

标定模式不实例化真实鼠标控制，不触发点击。

可以生成带准确物理尺寸说明的可打印标定板文件。注明打印必须 100% 实际尺寸、不使用“适合页面”，并要求用户实际量尺核验。

不把 OpenCV 返回的 RMS 简单当成参数协方差或绝对姿态精度。

## 六、坐标系与镜像规则

这是强制要求：

- 几何检测、摄像头标定与 PnP 尽量统一使用未镜像的原始图像。
- 自拍镜像只用于显示，保持现有手部 handedness 逻辑不受影响。
- 如需修改 camera.py，采用向后兼容接口，避免影响 FaceMesh 和 Hands。
- 不对镜像图像直接套用未镜像标定参数。
- 标记坐标系、相机坐标系、显示坐标系必须在文档中明确定义。
- 相机坐标系遵循 OpenCV：X 向右、Y 向下、Z 向前。
- 所有物理平移单位统一为米；UI 可换算为毫米显示。
- 标定分辨率与运行分辨率不一致时，本轮拒绝使用并提示重标定，禁止静默复用。
- 摄像头变焦、焦距或裁切变化可能使标定失效，README 中明确提醒。

## 七、阶段一：眼镜标记追踪

建议新增 eyemouse/glasses_tracker.py。

初版采用固定在镜框或轻便刚性支架上的单个 ArUco 标记：
- marker_id、dictionary、marker_size_m 可配置。
- 标记真实尺寸必须由用户测量，不能猜测。
- 固定位置尽量不遮挡眼睛，不影响眨眼检测。
- 说明小标记的像素尺寸、反光、侧转与遮挡会限制精度。
- 支持后续扩展到已知布局的多标记刚体，但本轮不强制实现。

对有效检测：
- 对角点进行适当亚像素精化。
- 使用与角点顺序严格一致的模型点。
- 使用 solvePnPGeneric + SOLVEPNP_IPPE_SQUARE 获取平面标记候选位姿。
- 严格遵守 OpenCV 对 IPPE_SQUARE 模型点顺序的要求。
- 不仅按重投影误差选解，还检查正深度、旋转有效性及时间连续性。
- 初次获取或长时间丢失后若候选解存在无法可靠区分的歧义，标记 ambiguous，不强行输出可信姿态。
- 连续性只辅助选择，不覆盖其他质量检查。

输出结构至少包含：
- valid、status、timestamp、marker_id。
- corners_px。
- rotation_matrix 或规范化 quaternion。
- translation_m。
- reprojection_error_px、marker_area_px。
- 原始与平滑位姿。
- 候选歧义或失效原因。

失效状态至少区分：
NO_MARKER、TOO_SMALL、AMBIGUOUS、BAD_REPROJECTION、
MOTION_OUTLIER、CALIBRATION_MISMATCH、STABILIZING、TRACKING。

## 八、异常拒绝与滤波

原则：先判断是否可信，再平滑。不能用重滤波掩盖错误位姿。

- 依据真实时间戳计算速度与角速度。
- 阈值配置化；长时间间隔后不能沿用旧帧速度判据。
- 旋转差使用旋转几何计算，不直接相减欧拉角。
- 旋转采用四元数连续性处理与 SLERP，或等价 SO(3) 方法。
- 平移使用独立滤波状态，不能与眼睛、手控共用。
- 欧拉角只用于 UI 展示。
- 丢失检测立即将当前观测标记无效。
- 可为 UI 显示短暂保留最后姿态，但保留值必须标记 stale，不能视为有效观测。
- 重新获取后连续若干个有效观测才能恢复 TRACKING。
- 重置陈旧滤波状态，避免从丢失前错误轨迹缓慢滑回。
- 报告有效帧率、失效计数和拒绝原因统计。

## 九、无鼠标验证模式

新增 CLI：
--glasses-test

要求：
- 只打开摄像头和调试窗口，不实例化真实鼠标控制、不注册会触发真实点击的动作。
- 保持退出方式清晰，支持 ESC，并按项目可行方式保留 F10。
- 显示标记边界、ID、三色坐标轴、Status、Reproj、
  Translation、Yaw/Pitch/Roll、TrackingFPS、有效观测比例。
- 姿态有效性与陈旧状态显著区分。
- 若内参文件缺失，提示先运行 --calibrate-camera。
- 本轮不使用粗略焦距替代真实标定后输出“可信”位姿。
- 提供定时数值统计，例如静止 10 秒的位置标准差和旋转角偏差。
- 统计旋转抖动不要直接对跨 ±180° 的欧拉角求标准差。
- 不记录图像。

现有 FaceMesh 对比可作为可选调试项：
- 同一静止区间比较各自相对平均朝向的角抖动及离群率。
- 两者坐标系未对齐前，不把绝对 yaw 差当成精度误差。
- 若影响 FPS，默认关闭对比。

## 十、阶段二设计：屏幕几何与指向控制（本轮不实现）

设计内容必须包括：

1. 估计屏幕相对摄像头的刚体变换与物理宽高。
2. 屏幕像素坐标与物理平面坐标的明确对应。
3. 个人指向方向的少量参数校准。
4. 使用眼镜位姿生成指向射线并与屏幕平面求交。
5. 不同时自由拟合屏幕几何、射线起点与方向，避免不可辨识。
6. 初版固定或约束眼镜坐标系中的射线起点，仅拟合方向偏差。
7. 对近平行、负向交点、非有限交点及离屏交点制定明确策略。
8. 追踪失效时冻结光标，不自动切回面部、眼控或手控。
9. 新来源与现有模式显式选择，不复用旧 MODEL_VERSION=3 眼控文件存储新几何模型。
10. 保留眼睛点击；确认眨眼冻结作用于最终光标输出，而不只是眼控分支。

特别注意：
装在屏幕上方、朝用户拍摄的摄像头通常无法看到自身所在屏幕或边框。
不能假设摄像头可以直接观察屏幕上的标记完成外参标定。

必须提出可执行的外参标定选项，例如：
- 测量摄像头与屏幕的相对位置和姿态，给出误差限制；
- 用摄像头可见、且与屏幕关系已知的刚性标定支架；
- 借助临时外部相机进行变换链标定。

首先推荐适合当前硬件的方案，用户确认后再实现。摄像头或屏幕移动后要求重新标定。
